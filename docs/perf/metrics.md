# Performance metrics: before / after

**Before** = commit `90f7db9` (the untouched app plus the measurement tooling). **After** = `main`.
Both were measured back to back on the same machine with the same scripts (`scripts/perf/measure.sh`,
tables generated by `scripts/perf/compare.mjs`). Nothing here is estimated.

- Lighthouse 13.6 CLI, mobile preset (simulated slow 4G, 4× CPU), headless Chrome with a fresh profile per run, 3 runs, median by score.
- Bundle: gzip −9 of each route's initial JS (`bundle-size.mjs`), plus `next experimental-analyze` (`bundle.html`).
- Render profile: `next build --profile --no-mangling`, React DevTools commit hook, Event Timing, Long Animation Frames, 4× CPU, median of 3.

Raw data: [`before-rerun/`](./before-rerun), [`after/`](./after), Phase 1 audit in [`before/`](./before),
non-virtualized vs virtualized 5,000-row runs in [`evidence/`](./evidence).

Targets: LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1. All dashboard pages meet them. The public home
page misses LCP (4.52 s simulated, 0.47 s observed); see PERFORMANCE_REPORT.md §13.
